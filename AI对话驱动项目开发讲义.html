一、项目概述与最终效果

1.1 项目背景

本项目基于一个已有的单片机按键检测程序（能检测 S4~S7 四个按键的按下/松开状态并在 OLED 上显示）。 在一次完整的 AI 对话过程中，通过 6 轮渐进式对话，将这个简单的电平检测程序， 逐步演化为一个具备计数、清零、启停控制、加减切换的完整人机交互系统。

1.2 最终实现的功能

按键功能说明
S7计数键每按一次计数 +1 或 −1（由方向决定，仅在"计数中"有效）
S4清零键按一次将计数归零（任何时候都有效）
S5启动/暂停复用键，每按一次切换工作状态
S6加1/减1 切换复用键，每按一次切换计数方向（仅在"已暂停"时可设置）

1.3 最终 OLED 显示效果

计数中 + 加1模式：
计数控制系统 记录次数：012 计数中 计数加1
暂停 + 减1模式：
计数控制系统 记录次数：012 已暂停 计数减1

1.4 开发流程全景

Step 1: 增加次数检测 → Step 2: 代码优化 → Step 3: 调整结构 → Step 4: 功能重构 → Step 5: 启停控制 → Step 6: 加减切换

二、与 AI 对话的核心原则

在开始 Step-by-Step 讲解之前，先总结本项目中与 AI 对话的 5 条核心原则。 这些原则贯穿每一轮对话，是高效协作的基础。

💡 五条核心原则
  • 原则 1：明确受众 — 开篇就告诉 AI "这是给初学者用的，逻辑要简单清晰"，AI 会自动避免引入指针、函数指针等高级概念
  • 原则 2：增量式描述 — 每次只提一个新需求，用"在当前功能基础上继续加上…"开头，AI 会在现有代码上叠加而非重写
  • 原则 3：指定按键 — 明确说"用 S5 按键实现"，避免 AI 自行分配引脚造成混乱
  • 原则 4：及时纠偏 — 如果 AI 的优化方向不对（如引入了不想要的宏定义），直接说"暂时不用，恢复原先状态"，AI 会立即回退
  • 原则 5：要求附说明 — AI 每次修改后都会输出"修改说明"，教师可直接用于课堂讲解
1
提出初始需求：从"电平检测"到"次数计数"
目标：在原有按键状态检测基础上，增加按下次数统计并显示
🙋 用户提问
"在当前程序的功能基础上，增加按键按下次数的检测，并在液晶屏幕上显示各按键的按下次数，超过100次则清零。请完成这个项目的改编设计，你这是给初学者进行引导式教学用的，逻辑要简单清晰。"
🤖 AI 响应要点
  • 先阅读项目结构和所有源文件（main.c、key.c、key.h、OLED 驱动），理解现有代码
  • 识别核心问题：原程序只检测电平（按下/松开），无法计数；需要新增按下事件检测（下降沿）
  • 在 key.c 新增 Key_S4_Pressed() 等函数（下降沿状态机：上次松开 + 本次按下 = 按下事件）
  • 在 main.c 增加计数变量，OLED 显示次数（布局：S4:按下 N=012）
  • 输出完整的"修改说明"，解释改动思路和显示布局
💡 对话技巧分析
  • "在当前程序的功能基础上" — 这句话告诉 AI 不要重写，而是在现有代码上增量添加。AI 据此保留了原有按键检测函数，只新增了 Pressed 函数
  • "给初学者进行引导式教学用的，逻辑要简单清晰" — 这句受众声明至关重要。AI 据此选择了最直白的 if-else 写法，而非函数指针数组等"高级"但难懂的方案
  • "超过100次则清零" — 给出明确的数值边界，AI 直接用 if (count == 100) count = 0; 实现，无需追问
📝 教学启示

第一轮对话的关键是"把话说全"：做什么 + 给谁用 + 有什么约束。AI 不是人，不会"猜你的意思"， 但只要你描述清楚，它能比人更快地分析整个代码库并给出精准的修改方案。

2
请求代码优化：让代码更适合教学
目标：优化 main 函数，提出优化理由，要求针对初学者
🙋 用户提问
"对主程序main函数进行优化，提出优化的理由。注意是针对初学者来讲的。"
🤖 AI 响应要点

AI 提出了两个优化点：

  • 优化一：宏定义消除"魔法数字" — 把 100、3、20 等裸数字改成 #define COUNT_MAX 100，理由："给数字起名字"，改阈值只改一处
  • 优化二：提取 Count_Add() 函数 — 把 4 处重复的"count++; if(count==100) count=0;"封进函数，理由："重复代码提成函数"，用返回值赋回避免指针

同时列出"不做哪些优化"表格：不用数组+循环（需函数指针过难）、不用局部变量替代全局（8051 栈有限），解释取舍理由。

💡 对话技巧分析
  • "提出优化的理由" — 不仅要求改代码，还要求解释为什么。AI 输出了"优化理由（讲给学生听）"小节，用口语化表达如"给数字起名字"，而非抛"DRY 原则"等术语
  • "针对初学者来讲的" — 再次强调受众。AI 据此控制了优化力度：做了宏定义和函数封装，但没有做数组+循环、函数指针等初学者看不懂的优化
  • AI 主动列出"不做哪些优化"的表格，这种取舍说明对教学非常有价值——让学生理解"好代码"不是越高级越好，而是越合适越好
📝 教学启示

向 AI 要"优化理由"而非只要"优化结果"，是教学场景的关键技巧。AI 生成的理由可以直接作为 课堂讲解素材。而强调"针对初学者"能让 AI 自动把握优化的"度"——既改进代码质量，又不引入 超出学生理解范围的抽象概念。

3
纠正优化方向：代码组织方式的调整
目标：去掉宏定义，改用"按功能阶段分组"的三段式结构
🙋 用户提问
"宏定义这个部分暂时不用，请恢复到原先的状态。把四个按键的检测按下事件归到一起，把四个按键的按下并放开事件归到一起，最后把按键次数的显示归到一起，按这个思路进行调整，你再修改一下"
🤖 AI 响应要点
  • 立即去掉宏定义和 Count_Add 函数，恢复裸数字写法
  • 将主循环从"按按键分组"改为"按功能阶段分组"（三段式）： 
    /* 第一阶段：四个按键的按下事件检测与计数 */
if (Key_S4_Released()==1) { count_s4++; ... }
if (Key_S5_Released()==1) { count_s5++; ... }
...

/* 第二阶段：四个按键的当前状态显示 */
if (Key_S4_Down()==1) { OLED_ShowChinese(..., "按下"); } ...

/* 第三阶段：四个按键的按下次数显示 */
OLED_ShowNum(88, 0, count_s4, 3); ...
  • 输出优化理由："程序流程一眼看清"、"先处理数据再显示数据的分层思想"
💡 对话技巧分析
  • "宏定义这个部分暂时不用，请恢复到原先的状态" — 这是及时纠偏的典范。AI 上一轮做的宏定义优化虽然"专业"，但教师认为对当前学生阶段不合适，一句话就让 AI 回退。AI 不会"坚持己见"，立即执行
  • "把…归到一起" 重复三次 — 用排比句式精确描述期望的代码组织结构。AI 准确理解了"按功能分组"而非"按按键分组"的意图
  • 这轮对话展示了 AI 协作的重要特性：你永远是决策者。AI 提建议，你定方向。不满意就直说，AI 会立刻调整
📝 教学启示

这是 6 轮对话中最有教学价值的一轮。它展示了三件事：① AI 的优化建议可以拒绝； ② 用排比句描述代码结构比说"重构"更有效；③ "按功能阶段分组"是嵌入式程序的基本架构思想—— 先采集数据、再处理数据、最后显示数据，层次分明。学生应重点理解这种"三段式"组织方式。

4
项目功能重构：计数控制系统
目标：重构为 S7 计数 + S4 清零的计数控制系统，设计人机界面
🙋 用户提问
"对按键的检测应用进行项目功能重构。设计一个按键按下次数的计数控制系统。针对按键s7按下的次数进行计数，并在液晶上显示。能对当前计数数值进行清零控制，用S4键实现。对液晶屏做一个人机交互界面的简单设计。第一行显示计数控制系统，第二行显示记录次数。"
🤖 AI 响应要点
  • 发现字模库缺少"计、数、记、录、次、清、零"等汉字，主动用 Python + PIL 从系统宋体生成 16×16 点阵字模，插入 OLED_Data.c
  • 重构 main.c：S7 计数、S4 清零，OLED 第一行标题"计数控制系统"，第二行"记录次数：012"
  • 标题和标签开机只画一次，主循环只刷新数字部分（优化显示效率）
/* 第一行：标题居中显示 */
OLED_ShowChinese(16, 0, "计数控制系统");
/* 第二行：标签 + 冒号 + 数字 */
OLED_ShowChinese(0, 16, "记录次数");
OLED_ShowString(64, 16, ":");
OLED_ShowNum(72, 16, count, 3);
💡 对话技巧分析
  • "第一行显示…第二行显示…" — 直接给出界面布局描述，AI 据此计算坐标（中文 16×16，数字 8×16），自动安排显示位置
  • AI 主动解决字模缺失问题 — 这是 AI 协作的突出优势。字模库缺字是个"隐藏问题"，用户可能都不知道。AI 发现后没有报错停下，而是自动生成字模数据并补充到字模库，让程序能编译通过
  • "功能重构"一词让 AI 理解这是整体重写而非增量修改，于是重新设计了 main.c 的结构和界面
📝 教学启示

这一轮展示了 AI 的自主解决问题能力。当遇到字模库缺字这种"卡点"时，AI 不是报错等待， 而是主动用工具生成字模数据。学生应理解：AI 不只是"写代码的打字员"，它还能分析问题、 调用工具、解决依赖。当然，最终字模是否正确还需要编译验证。

5
增量添加：启动 / 暂停控制
目标：S5 键切换启动/暂停，OLED 显示当前工作状态
🙋 用户提问
"在当前项目功能的基础上，继续加上启动计数和暂停计数的复用按键控制。用S5按键实现。并在液晶屏幕上显示当前人机交互工作状态：计数或暂停。请设计程序实现"
🤖 AI 响应要点
  • 新增状态变量 unsigned char running = 1;（1=计数中，0=已暂停）
  • S5 按下 → 翻转 running（toggle）；S7 按下 → 仅 running==1 时才 count++
  • 第三行显示"计数中"或"已暂停"
  • 发现缺"暂"字，再次用 Python 生成字模并补充
/* S5：切换 启动/暂停 */
if (Key_S5_Released() == 1) {
    if (running == 1) { running = 0; }  /* 计数中 → 暂停 */
    else            { running = 1; }  /* 暂停 → 计数中 */
}
/* S7：仅在计数中才 +1 */
if (Key_S7_Released() == 1) {
    if (running == 1) { count++; }  /* 暂停时按S7无效 */
}
💡 对话技巧分析
  • "在当前项目功能的基础上，继续加上…" — 这个开头成为后续每轮对话的标准模板。它明确告诉 AI：在现有代码上叠加，不要重写。AI 据此只新增了 running 变量和 S5 逻辑，原有 S7/S4 功能完整保留
  • "复用按键控制" — "复用"一词提示 AI 这是一个 toggle（翻转）按键，每按一次切换状态，而非按住有效。AI 用 if-else 翻转 running，对初学者清晰易懂
  • "用S5按键实现" — 明确指定按键，避免 AI 自行分配。之前 S7 计数、S4 清零已定，S5 用于启停是自然的延续
📝 教学启示

这一轮引入了状态变量 running——这是"状态机"思想的入门。 学生应理解：程序的行为不再只看按键，还要看当前状态。同一个 S7 键， 在"计数中"会 +1，在"已暂停"则无效。这就是状态机的精髓：输入 + 当前状态 → 行为。

6
增量添加：加1 / 减1 切换控制
目标：S6 键切换加1/减1模式，仅在暂停时可设置
🙋 用户提问
"在当前项目功能的基础上，继续加上计数加一和减一的复用按键控制。用S6按键实现。并在液晶屏幕上显示当前人机交互工作状态：计数加1或减1，只能在计数暂停的时候进行设置切换。请设计程序实现"
🤖 AI 响应要点
  • 新增第二个状态变量 unsigned char direction = 1;（1=加1，0=减1）
  • S6 按下 → 仅 running==0（暂停）时才翻转 direction
  • S7 按下 → running==1 时，direction==1 则 count++，direction==0 则 count--（带下溢保护）
  • 第四行显示"计数加1"或"计数减1"；补充"加、减"字模
/* S6：仅暂停时才能切换方向 */
if (Key_S6_Released() == 1) {
    if (running == 0) {           /* ← 关键：只有暂停才能设置 */
        if (direction == 1) { direction = 0; }
        else              { direction = 1; }
    }
}
/* S7：根据方向做加1或减1 */
if (Key_S7_Released() == 1) {
    if (running == 1) {
        if (direction == 1) { count++; }
        else { if (count > 0) { count--; } }  /* 减到0不再减 */
    }
}
💡 对话技巧分析
  • "只能在计数暂停的时候进行设置切换" — 这个条件约束是本轮的精髓。AI 据此在 S6 处理中加了 if (running == 0) 这层判断，计数中按 S6 无效。这体现了"设置只能在停止时进行"的交互逻辑（如调电子表时间）
  • 程序现在有 两个独立的状态变量：running（管"干不干"）和 direction（管"怎么干"）。AI 准确理解了这两个状态的独立性，没有混淆
  • AI 主动加了下溢保护 if (count > 0) count--;，防止 unsigned char 减到 0 后变 255。这种边界处理是 AI 作为"有经验的开发者"的体现
📝 教学启示

这是项目中最复杂的一轮。学生应重点理解三个概念：① 多状态变量——程序可以同时有多个 独立状态；② 条件限制——某些操作只在特定状态下有效（S6 只在暂停时有效）； ③ 边界保护——减到 0 不能再减，这是工程思维的基本素养。

9.1 最终代码结构（main.c 核心部分）

/* 三个全局状态变量 */
unsigned char count = 0;      /* 计数（0~255） */
unsigned char running = 1;    /* 1=计数中，0=已暂停 */
unsigned char direction = 1;  /* 1=加1，0=减1 */

void main(void)
{
    /* 初始化 + 画固定界面（标题/标签） */
    Key_Init(); OLED_Init(); OLED_Clear();
    OLED_ShowChinese(16, 0, "计数控制系统");
    OLED_ShowChinese(0, 16, "记录次数");
    OLED_ShowString(64, 16, ":");
    OLED_ShowChinese(0, 32, "计数中");
    OLED_ShowChinese(0, 48, "计数加");
    OLED_ShowString(48, 48, "1");
    OLED_Update();

    while (1)
    {
        /* 第一阶段：按键事件检测与处理 */
        /* S5→切换启停  S6→切换加减(仅暂停)  S7→计数  S4→清零 */
        ...

        /* 第二阶段：显示计数值、工作状态、计数方向 */
        OLED_ShowNum(72, 16, count, 3);
        /* 第三行：计数中/已暂停 */
        /* 第四行：计数加1/计数减1 */
        OLED_Update();
        DelayMs(20);
    }
}

十、AI 对话经验总结

10.1 有效的提问模式

📌 增量式开头

"在当前项目功能的基础上，继续加上…" — 让 AI 在现有代码上叠加，不重写

📌 指定实现方式

"用 S5 按键实现" — 明确指定硬件资源，避免 AI 自行分配

📌 声明受众

"给初学者用的，逻辑要简单清晰" — 控制 AI 的技术选型深度

📌 给出约束

"只能在暂停时切换" — 提供业务规则，AI 会翻译成 if 条件

📌 描述界面

"第一行显示…第二行显示…" — 直接给出布局，AI 自动计算坐标

📌 及时纠偏

"暂时不用，恢复原先状态" — 不满意就直说，AI 立即回退

10.2 AI 协作的优势与局限

方面AI 的优势需要注意的局限
代码分析 能快速阅读整个项目，理解函数调用关系和代码结构 对于大型项目可能遗漏上下文，需确认其理解是否正确
问题解决 主动发现并解决隐藏问题（如字模缺失），调用工具生成数据 生成的字模等数据需要编译验证，偶尔可能有格式问题
代码质量 自动添加边界保护（如下溢检查）、注释清晰、附带修改说明 有时优化方向不符合教学需求（如引入宏定义），需及时纠偏
增量开发 能在现有代码上精确叠加功能，不破坏已有逻辑 需用"在当前基础上"明确提示，否则可能重写

10.3 给学生的建议

📝 三条核心建议
  • 建议一：把 AI 当作"有经验但需要明确指令的助手" — 它技术很强，但不会猜你的意思。你说得越清楚（做什么、用什么、有什么约束），它做得越好
  • 建议二：一轮只提一个需求 — 不要一次抛出所有功能。每轮对话后先看结果、编译验证，确认没问题再提下一个。这样出问题容易定位
  • 建议三：你是决策者，AI 是执行者 — AI 提的优化建议可以拒绝，AI 写的代码需要你理解后再用。不要盲目接受，要问"为什么这样写"
