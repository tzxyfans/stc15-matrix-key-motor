1
创建矩阵按键模块：逐行扫描法
目标：从独立按键升级到 4×4 矩阵按键，掌握行列扫描原理
👤 用户
开启矩阵按键新学习内容。开发板跳线 J5 必须短接到矩阵按键侧。
模块命名为 matrix_key（与独立按键 key 区分），无键返回 KEY_NONE(0xFF)
🤖 AI
创建 matrix_key.h / matrix_key.c，采用逐行扫描法：
① 4条行线默认拉高 → ② 逐行拉低 → ③ 读4条列线 → ④ 某列为低则定位按键
消抖10ms + 等待放开（阻塞式 do-while）

硬件接线

信号引脚方向
ROW1~ROW4P3.0~P3.3输出（逐行拉低扫描）
COL1P4.4输入
COL2P4.2输入
COL3P3.5输入
COL4P3.4输入

按键值表（code 存 Flash 省 RAM）

// key_values[行][列]
code unsigned char key_values[4][4] = {
    {'7','8','9','A'},  // ROW1
    {'4','5','6','B'},  // ROW2
    {'1','2','3','C'},  // ROW3
    {'*','0','#','D'}   // ROW4
};
💡 知识点：为什么用矩阵按键？
  • 16个按键只需8个IO（4行+4列），比独立按键省一半IO
  • "逐行扫描法"：每次只拉低一行，读列线状态定位按键
  • code 关键字把不变的映射表放Flash，节省RAM
  • KEY_NONE=0xFF：与任何合法键值（0x30~0x44）都不冲突
✅ 本步成果

矩阵按键模块创建完成，编译通过。但此时用的是阻塞式扫描（do-while等待放开），为下一步重构埋下伏笔。

2
非阻塞重构：从"卡死"到"边沿检测"
目标：解决阻塞式扫描导致系统卡死的问题
👤 用户
阻塞式扫描有问题：按键一直按着会导致系统卡死，主循环无法执行其他任务。
🤖 AI
采用 key_now / key_last 边沿检测法，拆成两个函数：
① MatrixKey_Read() — 纯扫描，立即返回，不消抖不等待
② MatrixKey_Scan() — 边沿检测 + 消抖，按一次只触发一次

边沿检测核心逻辑

unsigned char MatrixKey_Scan(void)
{
    static unsigned char key_last = KEY_NONE;
    unsigned char key_now = MatrixKey_Read();

    /* 下降沿：上次无键 + 本次有键 = 刚按下 */
    if (key_now != KEY_NONE && key_last == KEY_NONE)
    {
        DelayMs(10);              // 消抖
        key_now = MatrixKey_Read();
        if (key_now != KEY_NONE) {
            key_last = key_now;
            return key_now;       // 返回键值
        }
    }
    key_last = key_now;
    return KEY_NONE;            // 无事件
}
💡 知识点：边沿检测 vs 电平检测
  • 电平检测：读当前状态，按住一直返回键值 → 适合点动控制
  • 边沿检测：检测状态变化（下降沿），按一次报一次 → 适合计数/切换
  • static 局部变量跨调用保持值，是实现边沿检测的关键
  • 非阻塞：不等待放开，主循环不会被卡死
✅ 本步成果

矩阵按键模块改为非阻塞设计。MatrixKey_Scan 用于边沿检测场景，MatrixKey_Read 为内部纯扫描函数。

3
矩阵按键控制电机：自动/点动双模式
目标：复刻第二讲独立按键功能，改用矩阵按键实现自动/点动双模式
👤 用户
按键功能分配：A=模式切换，B=正转/停止，C=反转/停止，D=参数确定，*=占空比+1，#=占空比-1
复刻第二讲功能：自动和点动两种模式，点动按住动松开停，自动按一次触发一次。OLED界面尽量用中文。
🤖 AI
两种模式需要不同的检测方式：
① 自动模式 → MatrixKey_Scan() 边沿检测，按一次触发一次
② 点动模式 → MatrixKey_GetState() 电平检测，按住持续返回
新增 MatrixKey_GetState() 函数（连续两次相同才稳定，实现消抖）

OLED 中文显示布局

先检查字模表是否包含所需汉字
电机控制 模式:自动 占空比:050% 状态:停止

字模表有"电机控制/模式/自动/点动/占空比/状态/停止/正转/反转"等全部所需汉字，只缺"矩/阵/键"三字，故标题用"电机控制"而非"矩阵按键控制"。

点动模式实现（状态驱动）

// 点动模式：按住B→正转，按住C→反转，其他→停止
unsigned char key_state = MatrixKey_GetState();

if (key_state == 'B') {
    Motor_Forward();   // 按住正转
} else if (key_state == 'C') {
    Motor_Reverse();   // 按住反转
} else {
    Motor_Coast();     // 松开即停
}
💡 知识点：互锁保护
  • 正转时按C忽略，反转时按B忽略 → 不能直接换向，必须先停止
  • 模式切换只能在停止时进行 → 运行中按A无效（安全保护）
  • 占空比调节运行中立即生效 → Motor_SetSpeed(duty)
✅ 本步成果

自动/点动双模式实现完成，OLED中文显示，编译0错误。但此时点动模式调用了两个函数（GetState + Scan），结构不够清晰。

4
主循环结构重构：公共处理前置
目标：A、*、# 统一提到模式判别之前，MatrixKey_Scan 只调用一次
👤 用户
A、星、井 用 MatrixKey_Scan()，统一放在模式处理之前安排，然后再分别进到两种模式的判别和处理。
🤖 AI
重构主循环：Scan 只调用一次，返回值同时用于公共处理和自动模式的 B/C 处理。
代码量从 16390 降到 16063（合并了重复代码）。

重构后的主循环结构

while (1)
{
    unsigned char key_evt = MatrixKey_Scan();   // 只调用一次

    /* ---- 公共处理（模式判别之前）---- */
    switch (key_evt) {
        case 'A': /* 模式切换 */ break;
        case '*': /* 占空比+1 */ break;
        case '#': /* 占空比-1 */ break;
    }

    /* ---- 模式相关：只处理 B/C ---- */
    if (mode == MODE_AUTO) {
        /* 复用 key_evt 边沿事件 */
    } else {
        /* 点动：MatrixKey_Read() 电平检测 */
    }
}
💡 知识点：代码结构优化
  • 公共逻辑前置 → 消除重复代码，减少code体积
  • Scan只调用一次 → 避免两次扫描间的状态不一致
  • 模式分支只处理差异部分（B/C检测方式不同）→ 结构清晰
5
简化为 MatrixKey_Read 版本
目标：去掉 MatrixKey_GetState 中间层，追求代码简洁
👤 用户
如果用 MatrixKey_Read 去掉static，用它替换掉 MatrixKey_GetState 函数会有什么影响？
🤖 AI
主要影响是丢失消抖：按下/松开瞬间的抖动会穿透到电机控制，可能产生"哒哒"异响。
但主循环10ms节拍与抖动5~10ms同量级，大部分时候没问题。
追求简洁可以替换，追求干净则保留 GetState。
👤 用户
简洁一点，改成 MatrixKey_Read 版本吧

两个函数对比

MatrixKey_ReadMatrixKey_GetState
消抖无，原始扫描值直接返回有，连续两次相同才更新
static变量无（每次独立）有 key_last + stable
代码量更少多一层封装
💡 知识点：简洁 vs 健壮的权衡
  • 教学项目追求简洁 → 去掉中间层，靠10ms主循环节拍隐式消抖
  • 工程项目追求健壮 → 保留显式消抖，不依赖外部节拍
  • 这是典型的设计权衡：没有绝对对错，看场景选择
✅ 本步成果

删除 MatrixKey_GetState，MatrixKey_Read 改为公开函数。代码量再省29字节。

6
数字键输入占空比
目标：数字键0~9输入两位数占空比，D键确认
👤 用户
实现读取数字按键键值并整理成占空比参数。占空比保存最近输入的两位数，按下确定后整理成一个数值更新到duty变量。
🤖 AI
用滚动缓冲公式：input_buf = (input_buf % 10) * 10 + (key - '0')
自动挤出最旧的位，保留最近两位。按D确认后 duty = input_buf。

滚动输入算法

// 例：按5→05，再按3→53，再按7→37（挤出最旧的位）
case '0': case '1': ... case '9':
    input_buf = (input_buf % 10) * 10 + (key_evt - '0');
    ShowDutyNum(input_buf);   // 预览
    break;

case 'D':
    duty = input_buf;
    Motor_SetSpeed(duty);     // 立即生效
    break;

💡 知识点：滚动缓冲技巧
  • (x % 10) * 10 + new：取个位升到十位，再拼上新数字
  • 不需要数组、不需要计数器，一个变量搞定两位滚动
  • 这是嵌入式开发中常用的环形缓冲简化版

人机交互优化：输入预览分区显示
目标：输入预览放第三行最右侧，确认后消隐，输入0则不变
👤 用户
把占空比输入的字符放在第三行最右侧。检测到数字按键按下就在这里显示最近两位数字。 按下确定键则更新为占空比数值，然后消隐掉。如果两位数结果是0，按下确定则占空比不变，直接消隐。

增加 input_active 标志位跟踪输入状态。
D键：非0→更新duty，为0→不变，然后消隐预览区。
A/*/#键：取消未确认输入，消隐预览区。

优化后的第三行布局

D键确认逻辑

case 'D':
    if (input_active) {
        if (input_buf > 0) {           // 输入非0 → 更新占空比
            duty = input_buf;
            Motor_SetSpeed(duty);
            ShowDutyNum(duty);
        }
        /* input_buf == 0 时占空比不变 */
        ClearInputNum();         // 消隐输入预览
        input_active = 0;
    }
    break;
💡 知识点：人机交互设计原则
  • 分区显示：当前值和输入预览分开，避免混淆
  • 实时预览：输入过程让用户看到正在输入什么
  • 安全默认：输入0时不改变当前值（避免误操作停机）
  • 可取消：切模式/微调时自动取消未确认的输入

AI 对话经验总结

1. 渐进式开发

从模块创建→非阻塞重构→电机控制→结构优化→简化API→数字输入→交互优化，每步都有明确目标，逐步叠加功能。

2. 先问再做

控制方案有多种可能时，先用question工具确认方案再动手。避免做完了才发现方向不对。

3. 设计权衡明示

简洁vs健壮（Read vs GetState）、公共前置vs模式内处理，把权衡利弊讲清楚让用户决策。

4. 注释中的陷阱

注释中写 A/*/# 会被C编译器当成注释结束符 */，改为"A、星、井"避免。这是C语言注释的经典坑。

5. 字模表验证

OLED中文显示前先检查字模表是否包含所需汉字。本项目缺"矩/阵/键"三字，标题改用"电机控制"。

6. 消抖的本质

消抖就是"连续多次读取相同才确认"。边沿检测用DelayMs(10)再确认，电平检测用连续两次相同。主循环节拍本身也是一种隐式消抖。
