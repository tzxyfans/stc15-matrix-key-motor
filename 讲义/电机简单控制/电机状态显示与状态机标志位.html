二 HMI 设计：像素账本与两行界面

屏幕怎么排？直接照抄本系列《计数控制系统设计》的"像素账本"方法：先算清楚每个字占多少像素，再定点落位，避免越界和残影。

（一）像素账本

参数取值与含义
屏幕分辨率128 × 64 像素，按 16px 行高可分为 4 行（y = 0 / 16 / 32 / 48）
汉字16 × 16 像素，每字占宽 16、占高 16
ASCII8 × 16 像素（本库默认大字 OLED_8X16），冒号、数字等占宽 8
本界面占用只用前两行：第一行标题、第二行"标签 + 状态"

（二）两行界面布局

① 第一行（y = 0）：标题"电机控制系统"

6 个汉字 × 16 = 96px，居中：x = (128 - 96) / 2 = 16。调用 OLED_ShowChinese(16, 0, "电机控制系统")。

② 第二行（y = 16）：标签"运行状态："+ 状态

标签用 OLED_ShowMixedText(0, 16, "运行状态:")：4 汉字（64px）+ 冒号（8px）= 72px，起于 x=0、止于 x=72。状态文字接在 x=72 处：OLED_ShowChinese(72, 16, "正转")。两字 32px，终址 x=104 < 128，安全。

⚠️ 残影坑：状态文字必须"等宽"
  • "正转 / 反转 / 停止"全部是 2 个汉字（32px），宽度一致
  • 每次切换，OLED_ShowChinese(72,16,...) 都是把同一块 32×16 区域整块覆盖重画
  • 若某状态用 3 个字（如"运行中"），改写 48px 会盖不住前一个 32px 的笔画 → 残留鬼影。本讲故意统一取 2 字规避
💡 OLED 两步机制（与计数系统一致）：所有 OLED_ShowXxx 只是往显存里写，屏幕不会立刻变；必须最后调一次 OLED_Update() 才把显存整体推到屏幕上。所以"画界面"和"上屏"是两件事。

三 状态机标志位：state 变量登场

本讲最大的新东西不是 OLED，而是一个全局变量 state。它让程序第一次有了"记忆"——记住"电机现在处于什么状态"。

（一）为什么需要 state

上讲的程序里，电机转不转只有"电机自己"知道，main.c 里没有任何变量记录"当前状态"。按键一多、逻辑一复杂（比如下一讲要同时管"模式 + 运行 + 方向"），没有状态变量就会乱成一锅粥。state 就是专门用来"记住当前状态"的状态寄存器。

（二）state 的定义与取值

unsigned char state = 0;   /* 电机运行状态：0 = 停止，1 = 正转，2 = 反转（开机默认停止） */
🔍 三个"为什么"
写法原因
unsigned char状态只有几个值，1 字节足够；相比 int 更省 RAM，也最像真实的"硬件状态寄存器"
取值 0 / 1 / 2连续编号，方便用 if / else if 分派；将来想扩展（加刹车=3）只加一个值，不破坏结构
初值 = 0开机即"停止"，与电机模块默认惯性停转的安全态一致，避免上电瞬间误动作

（三）state 的双向数据流

🧩 标志位的本质：用一个变量记住"系统当前状态"，让"发生了什么"（按键事件）和"要显示 / 要做什么"（输出）彻底解耦。这正是状态机的最小雏形：状态 = 变量，转移 = 按键事件，输出 = 显示 + 电机动作。下一讲会把它扩展成多个标志位协同。

四 main.c 精讲：两段式主循环

程序结构非常清楚：初始化三段 → 主循环里"先处理按键（写 state），再据 state 刷新显示"。下面逐段拆开。

（一）头文件与全局变量

#include "key.h"
#include "motor.h"
#include "OLED_STC15.h"

unsigned char state = 0;   /* 电机运行状态：0 = 停止，1 = 正转，2 = 反转（开机默认停止） */

比上讲多了 OLED_STC15.h 和 state 全局变量。三个模块的头文件像三张名片，main.c 只认函数名、不碰内部实现。

（二）初始化：画好"静态界面"，上屏一次

Key_Init();              /* 按键初始化：准双向口 + 历史状态清零 */
Motor_Init();            /* 电机初始化：默认惯性停转（安全状态） */
OLED_Init();             /* OLED 初始化（内部先延时，待供电稳定） */

OLED_Clear();            /* 清空显存 */
OLED_ShowChinese(16, 0, "电机控制系统");   /* 第一行标题，居中 x=16 */
OLED_ShowMixedText(0, 16, "运行状态:");      /* 第二行标签，开机只画一次 */
OLED_ShowChinese(72, 16, "停止");          /* 初始状态：停止 */
OLED_Update();           /* 把界面先刷上屏 */
📌 要点：标题和"运行状态："是固定不变的标签，只在开机画一次，之后绝不重画（避免每帧闪烁、浪费）。会变的只有后面的状态二字，交给主循环处理。

（三）主循环：两段式

while (1)
{
    /* 第一阶段：按键事件检测与电机动作分发（同时写 state） */
    if (Key_S4_Released() == 1)  { Motor_Forward();  state = 1; }
    if (Key_S5_Released() == 1)  { Motor_Coast();    state = 0; }
    if (Key_S6_Released() == 1)  { Motor_Reverse();  state = 2; }

    /* 第二阶段：据 state 刷新第二行状态文字 */
    if      (state == 1)  OLED_ShowChinese(72, 16, "正转");
    else if (state == 2)  OLED_ShowChinese(72, 16, "反转");
    else              OLED_ShowChinese(72, 16, "停止");
    OLED_Update();
}
设计要点为什么这样写
静态界面开机画一次标题 / 标签不变，放初始化里画，循环只刷状态，避免每帧重画闪烁
动作与 state 同步每次下发电机指令，必紧跟 state = N，保证"电机实际动作"与"程序记忆的状态"永远一致
显示靠 state 分派把"显示什么"集中到一处 if/else if，而非在每个按键分支里各画一次——改显示只改这一块
仍用 Released 事件"按一下松一下"才切换一次状态，长按不会反复刷指令，语义自然
主循环没有 DelayMs事件式检测无需固定扫描节拍；刷新频率由 OLED_Update 耗时与循环自然形成
📚 本讲小结：main.c 眼里依然只有两件事——"初始化三个模块" 和 "循环里问三键、命中就下令 + 按 state 刷新屏幕"。复杂度被 motor / key / OLED 三模块吃掉了，state 则当起了"状态中转站"。

五 对比上次程序：无显示版 vs 状态显示版

把"上次（按键控制电机，无显示）"和"本次（按键 + OLED 状态显示）"并排，看清这次演进到底改了什么。

（一）上次的 main.c（无显示版，作对照）

#include "key.h"
#include "motor.h"

void main(void)
{
    Key_Init();   Motor_Init();
    while (1)
    {
        if (Key_S4_Released() == 1)  Motor_Forward();
        if (Key_S5_Released() == 1)  Motor_Coast();
        if (Key_S6_Released() == 1)  Motor_Reverse();
    }
}

（二）逐维对比

维度上次：按键控制电机（无显示）本次：按键 + OLED 状态显示
模块组合key + motorkey + motor + OLED
状态变量无，动作直接下发有 state（0/1/2）串联动作与显示
人机交互无，靠听声音 / 看转轴OLED 两行：标题 + 实时状态
主循环结构一段式：轮询三键 → 调电机两段式：①事件→动作+写 state ②读 state→刷显示
状态可见性状态只存在于电机本体状态显式存于变量，可读可显示
可扩展性加功能要改主循环逻辑state 成"状态中心"，加模式只加一个 flag
💡 洞察：这次升级的"灵魂"不是 OLED（那只是把 state 显示出来的窗口），而是 state 变量——它让程序第一次有了"记忆"。没有它，再多屏幕也只会机械重画；有了它，才谈得上"状态机"。

六 知识点小结与易错点

把本讲知识点串成一张网，调试时照着查。

（一）知识点清单

类别要点
OLED 使用Init → Clear → ShowXxx（写显存）→ Update（上屏）；两步机制；本库默认大字 8×16，中文 16×16
像素账本屏 128×64、行高 16、汉字 16 宽；状态文字取等长 2 字防残影
state 标志位unsigned char state，0/1/2 表停止/正转/反转；初值 0 = 安全
双向数据流按键事件"写"state，显示逻辑"读"state，state 作中转站解耦
两段式主循环①事件检测 + 动作 + 写 state ②据 state 刷新显示 + Update
模块化复用motor / key 原样复用，新增 OLED 不碰驱动，加显示只加一个模块

（二）易错点排雷

⚠️ 雷 1：只调了 Motor_Xxx，忘了写 state
  • 现象：电机动了，屏幕却不变——动作与显示脱节
  • 原则：下发电机指令的同时必须 state = N，两者永远成对出现
⚠️ 雷 2：把状态文字写进按键分支（每键各画一次）
  • 现象：显示逻辑散落三处，改个字要改三遍，容易改漏
  • 原则：显示集中到 if/else if(state) 一处，按键分支只负责"写 state"
⚠️ 雷 3：标题 / 标签放进 while(1) 每帧重画
  • 现象：屏幕闪烁、CPU 空转
  • 原则：不变的内容只在初始化画一次
⚠️ 雷 4：状态文字不等宽导致残影
  • 现象：切换状态后旧字笔画残留
  • 原则：所有状态值取相同字数（本讲统一 2 汉字），整块覆盖

🚀 下一讲预告：电机控制系统的"自动 / 点动"双模式

本讲用 state 记住了"电机在不在转"。但真实设备常有两种操作方式，只用"正转 / 反转 / 停止"还不够：

  • 🔁 自动模式：按一下启动键，电机自己持续转（自锁 / 锁存），再按一下才停——一个 running 标志位即可描述
  • 👆 点动模式：按住按键电机转、松手立刻停（非自锁）——这是"另一种按键控制设计"：不再用 Released 事件，改用 Down 电平（按住 = 转，松开 = 停），或"点动键 + 方向键"组合
  • 🧩 多标志位协同：下讲引入 mode（自动 / 点动）+ running（运行 / 停止）+ direction（正 / 反），用它们统一描述"系统处于什么模式、电机现在转不转、往哪转"
  • 🎯 设计重点：把"点动"这种"按住才动、松手就停"的按键逻辑，用清晰的标志位状态机设计出来
