2
学习参考项目：改用 PCA 8 位 PWM
目标：按参考项目 lesson3_motor 的方式，用 PCA 模块1 输出 21.6KHz PWM
🤖 AI 学习参考项目后的发现
  • 参考项目用 PCA 模块1（CCP1=P1.0）的 8 位 PWM 模式，不是高级 PWM 发生器
  • PCA 时钟 = SYSclk/2 = 5.5296MHz，8 位 PWM 频率 = 5529600/256 = 21600Hz ≈ 21.6KHz
  • 关键配置：CCAPM1=0x42(ECOM+PWM)，PCA_PWM1=0x00(8位PWM)
  • 占空比：CCAP1L = duty×256/100，duty=50% → CCAP1L=128
  • 寄存器全在 sfr 空间，不需要 P_SW2 EAXFR 扩展访问
✨ PCA 8 位 PWM 原理（重点知识）

PCA 有一个 8 位计数器 CL（0→255 循环），每个模块有自己的比较值 CCAPnL。

// 8位PWM输出规则（PCA_PWM1 的 EBS[1:0]=00 时）：
// 当 CL < CCAP1L 时，P1.0 输出低电平(驱动)
// 当 CL >= CCAP1L 时，P1.0 输出高电平(不驱动)
// 低电平占空比 = CCAP1L / 256 = 电机驱动占空比

// 频率 = PCA时钟 / 256 = 5529600 / 256 = 21600Hz ≈ 21.6KHz
// 占空比50% → CCAP1L = 128 = 0x80
💡 对话技巧
  • 用户提供参考项目是最高效的纠偏方式——不用描述该怎么做，直接给样板
  • AI 读取参考项目全部关键文件后，才动手重写，避免再次跑偏

4
CMOD 寄存器纠错：0x01 vs 0x02
目标：修正 CMOD 配置，使 PWM 频率真正为 21.6KHz
🙋 用户提问
"你程序里 CMOD = 0x01，但按 STC15F2K60S2 官方手册 SFR 表，CMOD 的 CPS 位在 B3~B1、ECF 在 B0，0x01 只置了 ECF，CPS=000 = 系统时钟/12。实际频率是 3.6KHz，不是 21.6KHz。你认真核对一下。"
🤖 AI 核对结果

用户完全正确。CMOD 位分布（官方手册）：

// bit7=CIDL  bit6~4=保留  bit3~1=CPS[2:0]  bit0=ECF
// CPS=001(SYSclk/2) 需把 bit1 置1 → CMOD=0x02
// 0x01 是 bit0=1(ECF=1) + CPS=000(SYSclk/12) → 3.6KHz ❌
// 0x02 是 bit1=1(CPS=001) + ECF=0 → 21.6KHz ✅

参考项目 pca.c 用 (cps & 0x07) << 1 把 CPS 放到 bit3~1，PCA_CPS_SYSCLK_DIV2=0x01 左移1位 = 0x02。

⚠️ 易错点永久记录
  • 根因：把 CPS 枚举值（0x01）直接当 CMOD 值写，忽略了 CPS 在 bit3~1 而非 bit2~0
  • 正确写法：CMOD = (cps & 0x07) << 1，或查表：SYSclk/12→0x00, SYSclk/2→0x02, SYSclk→0x08
  • 防范：写寄存器配置时，注释里必须标注位分布出处（"bit3~1=CPS, bit0=ECF"），方便核对
💡 对话技巧
  • 用户查手册核对是最高质量的纠错——不是凭感觉，而是给出官方依据
  • AI 被纠错后应立即读取参考项目确认，而不是争辩
  • 纠错后把易错点写入注释和记忆，避免重犯

加入按键控制：占空比调节与正反转
目标：S6/S7 调占空比，S4/S5 正转/停止、反转/停止复用，第四行显示状态
🙋 用户提问
"S6/S7 按键作为调节占空比使用，每按下1次做加减1，在1-100范围。S4、S5 按键作为正转/停止、反转/停止的复用按键。第四行显示 状态：正转/反转/停止"
🤖 AI 响应要点
  • 用 Key_Sx_Released() 放开事件检测（按一次触发一次，避免长按连跳）
  • 状态机三态：STOP / FWD / REV
  • S4：正转↔停止复用；S5：反转↔停止复用
  • 局部刷新：只重画变化的行，不闪烁
  • 主循环 DelayMs(10) 兼做按键消抖
✨ 状态机设计
#define STATE_STOP   0
#define STATE_FWD    1
#define STATE_REV    2

// S4：正转/停止 复用
if (Key_S4_Released()) {
    if (state == STATE_FWD) { Motor_Coast(); state = STATE_STOP; }
    else                    { Motor_Forward(); state = STATE_FWD; }
}
6
互锁保护与高位 0 消隐
目标：正转不能直接切反转；OLED 数字高位 0 消隐
🙋 用户提问
"加上控制条件，在正转的时候不能立即反转，反之亦然。显示数字的时候，如果高位是0，就消隐掉这个0，把 OLED 显示模块的功能加一个函数进去。"
🤖 AI 响应要点
  • 互锁：S4 在反转状态时忽略，S5 在正转状态时忽略，必须先停止再切换
  • 新函数 OLED_ShowNumNoZero(X,Y,Num,Len)：高位连续0用空格代替，最后一位保留
  • 效果：50→" 50"，1→" 1"，100→"100"
✨ 互锁逻辑
// S4：正转/停止 复用（互锁：反转时按 S4 忽略）
if (Key_S4_Released()) {
    if (state == STATE_FWD)       { /* 正转→停止 */ }
    else if (state == STATE_STOP) { /* 停止→正转 */ }
    /* state == STATE_REV 时忽略 */
}
💡 工程思维
  • 互锁是安全保护：直接从正转切反转，电机承受反向电流冲击，可能损坏驱动管
  • 高位0消隐是显示美化：避免"050"这种前导零，更符合阅读习惯
  • 两个需求都是增量式叠加，不破坏已有功能

PCA 模块化重构：改一个宏切换引脚
目标：支持 PCA 模块0/1/2 任意切换，使移植更便捷
🙋 用户提问
"设计程序并讲解使用 PCA 另外两组中的任意一组来控制电机，应该怎么调整程序，使得程序的模块化移植更便捷。"
🤖 AI 响应要点
  • motor.h 加宏 #define MOTOR_PCA_MOD 1（改 0 或 2 即切换模块）
  • motor.c 加 6 个 switch 封装函数（C51 sfr 不能取地址，只能 switch 分发）
  • 引脚推挽配置也按模块号自动选择（PCA_ConfigPin）
  • 讲解 CCPn_m 标记：n=模块号，m=引脚组号
✨ 模块化设计核心

问题：C51 的 sfr 寄存器不能取地址（&CCAP1L 非法），不能用指针数组统一访问。

解法：宏选模块 + switch 封装寄存器访问。

// motor.h — 改这一个宏即可切换
#define MOTOR_PCA_MOD  1   // 0=CCP0(P1.1) 1=CCP1(P1.0) 2=CCP2(P3.7)

// motor.c — switch 封装，按模块号分发到对应 sfr
static void PCA_wr_CCAPL(unsigned char mod, unsigned char val) {
    switch (mod) {
        case 0: CCAP0L = val; break;
        case 1: CCAP1L = val; break;
        case 2: CCAP2L = val; break;
    }
}

这是 STC15 多模块外设（PCA/串口/定时器）的通用移植手法。

三、复盘总结

📋 选型阶段

先确认资料可读性再选方案。STC15 有两套 PWM 硬件，PCA 寄存器在 sfr 空间更简单。参考项目是最好的方案指南。

🔧 配置阶段

寄存器位分布必须查官方手册 SFR 表，不能凭直觉。CMOD 的 CPS 在 bit3~1，SYSclk/2 需写 0x02 不是 0x01。

🎮 功能扩展

增量式叠加：先加按键控制，再加互锁保护，再加显示美化。每步只改一个点，不破坏已有功能。

📦 工程化

宏选模块 + switch 封装寄存器，实现"改一个宏切换引脚"。引脚归属唯一，main 只调接口。

💡 与 AI 协作的核心经验
  • 给样板比描述需求更高效：Step 1 描述需求 AI 跑偏，Step 2 给参考项目立刻修正
  • 查手册核对是最强纠错：Step 4 用户查手册发现 CMOD 位分布错误，比凭感觉纠错更有说服力
  • 增量式描述避免重写：每次"在当前功能基础上加上…"，AI 在现有代码叠加而非重写
  • 纠错后写入注释和记忆：CMOD 易错点写入代码注释 + 记忆文件，避免重犯
  • 模块化是渐进的：从 main 硬编码 → motor 模块 → 宏选模块，逐步演进而非一步到位
