⚡ PCA 三模块对照与移植 —— 一行宏切换 PWM 引脚

第一章项目任务与运行效果（对比上一讲）

上一讲（PWM②）我们让 S4~S7 控制占空比、启停和方向，电机转得很听话了。但有一个"硬伤"：底层 PWM 是写死在 PCA 模块1 的——直接操作 CCAP1L、引脚固定在 P1.0。如果某块板的 P1.0 被别的外设占用了，难道要把 motor.c 整个抄一遍、把所有 CCAP1L 改成 CCAP0L 或 CCAP2L？

1.1 本讲要解决的事

把"到底用哪个 PCA 模块"做成一个可配置项：写在 motor.h 顶部的宏里，改一个数字，PWM 引脚就跟着变，其余代码一行都不用动。这就是"模块化移植"。

1.2 和上一讲的区别（一眼看懂）

对比维度上一讲 PWM②（固定模块1）本讲（可移植）
使用模块写死模块1宏 MOTOR_PCA_MOD 选 0 / 1 / 2
PWM 引脚写死 P1.0随宏变 P1.1 / P1.0 / P3.7
寄存器访问直接写 CCAP1L 等统一经 switch 封装函数
换引脚要改改 motor.c 多处只改 motor.h 一行
main.c不变不变（都用 Motor_* 接口）
💡 一句话总结：上一讲是"把功能跑通"，本讲是"把功能做可移植"。控制逻辑完全一样，差别只在底层寄存器怎么被访问。

1.3 运行效果

同一份 main.c 和 motor.c，只把 motor.h 里 #define MOTOR_PCA_MOD 1 改成 2，电机照样按按键调速——唯一的变化是：示波器（或 LED 指示）上看到的 PWM 方波，从 P1.0 移到了 P3.7。OLED 显示内容、按键行为完全不变。

第二章PCA 三模块的寄存器与引脚对照（默认 CCP_S=00）

STC15F2K60S2 片内 PCA 有 3 个独立比较模块（模块0/1/2），它们共用同一个计数器 CL/CH 和 CMOD/CCON，只是各自的"比较值寄存器"独立。所以——三组输出的 PWM 频率完全相同（都由 CL/CH 决定，都是 21.6 kHz），差别只在"从哪个引脚出来"。

2.1 三模块寄存器 / 引脚对照表

模块模式寄存器比较值 L比较值 HPWM 控制引脚推挽配置
0CCAPM0 (0xDA)CCAP0L (0xEA)CCAP0H (0xFA)PCA_PWM0 (0xF2)P1.1P1M0 |= 0x02
1CCAPM1 (0xDB)CCAP1L (0xEB)CCAP1H (0xFB)PCA_PWM1 (0xF3)P1.0P1M0 |= 0x01
2CCAPM2 (0xDC)CCAP2L (0xEC)CCAP2H (0xFC)PCA_PWM2 (0xF4)P3.7P3M0 |= 0x80

上表是在默认引脚映射 CCP_S=00（即 P_SW1 的 bit5:4 = 00）下的对应关系，本工程不配置 P_SW1 即走默认值。三个模块的地址是"错开一个字节"的规律：模式寄存器 0xDA/0xDB/0xDC，比较值 L 0xEA/0xEB/0xEC……很好记。

⚠️ 易混点：模块2 的引脚是 P3.7。本工程按键都接在 P3.0~P3.3，P3.7 是空闲的，二者不冲突。但要注意——如果你之前做过"用 P3.7 做方向 DIR"的实验，选模块2 时就得把 DIR 让出来（正如我们曾把 DIR 改到 P0.4 释放 P3.7 那样）。

第三章如何切换到模块 0 或模块 2（改一行宏）

关键就在 motor.h 顶部这一个宏。它用 #ifndef 包着，意味着：如果你在工程别处（如 main.c 顶部）先 #define MOTOR_PCA_MOD 2，这里会自动跳过，以你的为准。

3.1 这一行宏决定了引脚

/* motor.h 顶部：PCA 模块选择 */
#ifndef MOTOR_PCA_MOD
#define MOTOR_PCA_MOD  0    /* 改用模块0 → PWM 输出在 P1.1 */
#endif

只要把 0 改成 2：

#define MOTOR_PCA_MOD  2    /* 改用模块2 → PWM 输出在 P3.7 */

🛡️ 设计要点：改这一行，其余都不用动

main.c：只调用 Motor_Forward / Motor_Reverse / Motor_SetSpeed 等接口，根本不知道底层用的是哪个模块——所以不用动。

motor.c：所有寄存器访问都写成"按模块号分发"的形式（下一章细讲），能自动识别 MOTOR_PCA_MOD 的值去操作对应的 CCAPnL——所以也不用动。

引脚推挽配置也由 PCA_ConfigPin() 按模块号自动选，不用你手写 P3M0 |= 0x80。

第四章模块化移植的设计核心（C51 限制与 switch 封装）

为什么不能直接写"我想用第 n 个模块的 CCAPnL"，而要绕一圈用 switch？根子出在 C51 编译器的限制上。

4.1 问题：sfr 寄存器不能取地址

在 C 语言里想"统一访问"一组同类资源，本能会想到用指针数组：

/* ❌ 这是错误的写法，C51 编译不过 */
unsigned char *p[3] = {&CCAP0L, &CCAP1L, &CCAP2L};
p[mod] = val;   /* 想用第 mod 个模块的比较值 */

但 sfr 是 C51 对特殊功能寄存器的"名字映射"，编译器并不给它分配普通内存地址，&CCAP1L 在 C51 里是非法的。所以指针数组这条路被堵死了。

4.2 解法：switch 按模块号分发到对应 sfr

既然不能"用变量选寄存器"，那就用 switch 把模块号翻译成具体的寄存器名。本工程里写了 6 个这样的封装函数，覆盖所有需要访问的 PCA 寄存器：

  • PCA_wr_CCAPM() —— 写模式寄存器 CCAPMn
  • PCA_wr_CCAPL() —— 写比较值低字节 CCAPnL（占空比核心）
  • PCA_wr_CCAPH() —— 写比较值高字节 CCAPnH（重装值）
  • PCA_wr_PWM() —— 写 PWM 控制 PCA_PWMn（选 8 位）
  • PCA_rd_CCAPL() —— 读 CCAPnL（判断 PWM 是否在运行）
  • PCA_ConfigPin() —— 配置对应引脚为推挽输出

以写比较值低字节为例，看它长什么样：

static void PCA_wr_CCAPL(unsigned char mod, unsigned char val) {
    switch (mod) {
        case 0: CCAP0L = val; break;
        case 1: CCAP1L = val; break;
        case 2: CCAP2L = val; break;
        default: break;
    }
}

4.3 调用方只认"模块号"，不认具体寄存器

所有对外/对内的逻辑函数，都通过这层封装 + MOTOR_PCA_MOD 宏来访问寄存器，自己是"模块号无关"的。例如启动 PWM：

static void PWM_Start(void) {
    unsigned char val = (unsigned char)(s_duty * 256 / 100);
    PCA_wr_CCAPH(MOTOR_PCA_MOD, val);   /* 重装值，保证占空比稳定 */
    PCA_wr_CCAPL(MOTOR_PCA_MOD, val);   /* 当前值，立即生效 */
}

把 MOTOR_PCA_MOD 从 1 改成 2，这里一行都不用改：PCA_wr_CCAPL(MOTOR_PCA_MOD, val) 在运行时自动走进 case 2: CCAP2L = val;，PWM 就乖乖从 P3.7 出来了。引脚推挽也同理——PCA_ConfigPin() 里 case 2: P3M1 &= ~0x80; P3M0 |= 0x80; 自动把 P3.7 设成推挽。

🧩 这是 STC15 多模块外设的通用移植手法：凡是一个外设有多组同质模块（PCA 模块0/1/2、串口1/2/3/4、定时器0/1/2/3/4……），移植时都遵循两句话——① 用宏选模块号；② 用 switch 封装寄存器访问。掌握这一个套路，换模块、换引脚就再也不用"抄代码"了。

第五章工程读写链路：从 main 到引脚的自动分发

把上面的调用关系串成一条链：上层只说"我要正转"，中间层翻译成"给某个模块的比较值赋个值"，最底层 switch 把它落到具体的 sfr 和引脚。整条链路中，只有 MOTOR_PCA_MOD 这一个数字是"开关"。

第六章完整小结、易错点与练习

6.1 本讲三件事

主题核心结论
三模块对照共用 CL/CH/CMOD/CCON，比较值寄存器独立；默认 CCP_S=00 下引脚为 P1.1 / P1.0 / P3.7，频率都是 21.6KHz
如何切换改 motor.h 一行 MOTOR_PCA_MOD 宏（0/1/2），引脚随之变，main.c 与 motor.c 其余不动
移植核心C51 的 sfr 不能取地址，用 switch 封装函数按模块号分发；宏选模块 + switch 封装是 STC15 多模块外设通用手法

6.2 五个初学者易踩的坑

  1. 以为换模块频率会变——错。三组共用 CL/CH，频率一样都是 21.6KHz，变的只是引脚。
  2. 直接写 CCAP1L 而不是走封装——一旦要换模块，就得满文件改，破坏了移植性。
  3. 忘了配引脚推挽——准双向口边沿太慢，PWM 波形发软、电机异响甚至不转；必须 PxM0 |= ...。
  4. 用 &CCAP1L 取地址——C51 里非法，编译报错；正确做法是用 switch 封装。
  5. 引脚映射搞错——以为模块2 一定在 P1.x；实际要查 P_SW1 的 CCP_S 位，本工程默认 00 才对应 P3.7。

6.3 动手练一练

  • 把 MOTOR_PCA_MOD 改成 0，用 LED 或示波器确认 PWM 移到了 P1.1；再改回 1 确认回到 P1.0。
  • 在 PCA_ConfigPin() 里加一行注释，写出模块1 推挽配置 P1M0 |= 0x01 对应的位含义（M1=0, M0=1）。
  • 想一想：如果用串口2（S2CON 等），要用哪两个套路做可移植？（提示：宏选串口号 + switch 封装）
