一 项目任务与承上启下：给系统装上"总开关"

项目五的系统有个"老实过头"的毛病：只要上电，S7 永远都在计数——它不会停。上一讲结尾预告过要给系统装一个"总开关"，本讲兑现：用 S5 一键控制启动计数 / 暂停计数，并把工作状态显示到 OLED 第三行。

（一）新系统：一个键，两种状态

（二）本讲的需求清单

按键 功能 生效条件
S7计数键：按一次 +1仅在"计数中"状态下有效，暂停时按无效
S4清零键：按一次计数归零无门控 任何时候都有效
S5启动 / 暂停复用键：按一次切换工作状态按一次翻转一次（toggle）
OLED 第三行显示当前工作状态"计数中" / "已暂停"开机画初始状态，主循环随状态刷新

🎯 承上启下：这一讲是"功能生长"的第二次实践。项目五是"界面生长"（有脸面），本讲是"行为生长"（有状态）。骨架（三段式主循环）和积木（按键、OLED 驱动）都没动，只在事件处理段里多了一个状态变量、多了一层判断——好的结构，就是让新功能"长"进去而不是"塞"进去。

二 核心概念：状态变量 running——系统"记得自己在干嘛"

在项目五之前，程序的行为只取决于一件事：哪个键被按下了。本讲开始，行为多了一个决定因素：系统现在处于什么状态。这两者的区别，就是"单片机照着按键执行" 和 "单片机有主意地执行" 的分水岭。

（一）变量的定义：给"现在在干嘛"起个名字

unsigned char count = 0;      /* 按下次数计数（0~255，S4 清零） */
unsigned char running = 1;    /* 工作状态：1 = 计数中，0 = 已暂停（开机默认计数） */
要点 为什么
用 1 和 0 表达状态只有两种状态，一个字节绰绰有余：1 = 计数中、0 = 已暂停。变量的名字 running 直接说出了含义——读代码的人一眼就懂
必须是全局变量主循环每一帧都要读它、判断它，生命周期必须贯穿整个程序；与 key.c 里的 static 历史状态一样，是"系统的记忆"
开机默认值 = 1上电即默认"计数中"，与第三行开机画面"计数中"保持一致——初值和开机画面必须对得上，否则一开机就显示错状态
也可以用 bit 类型bit 只占 1 位更省 RAM，但 unsigned char 更通用、可读性一致，习惯统一

（二）同样的按键，不同的状态，不同的行为

把"按键 × 状态"列成一张真值表，程序逻辑一目了然——这张表就是设计文档：

按键事件 running = 1（计数中） running = 0（已暂停）
S7 放开count++（计数 +1）无动作 事件被状态"挡住"
S4 放开count = 0（清零）count = 0（清零）——不受状态影响
S5 放开running = 0（暂停）running = 1（启动）

（三）状态机思想的入门

🧠 状态机（State Machine）三要素：状态（State，系统现在处于哪一格）、事件（Event，什么输入引发了变化）、动作（Action，变化时与保持时分别做什么）。把这三件事分开想清楚再落笔，程序自然清晰——这就是"状态机思想"给初学者上的第一课。
现实世界里到处都是状态机：洗衣机的"洗涤 / 漂洗 / 脱水"，红绿灯的"红 / 绿 / 黄"，电梯的"上行 / 下行 / 空闲"。本讲的"计数中 / 已暂停"，是你能写出来的最小一台。

三 复用按键 S5：什么叫 toggle 翻转

一个物理按键承担两个功能，靠什么区分？靠系统当前的状态：S5 在"计数中"时的含义是"暂停"，在"已暂停"时的含义是"启动"。这种"按一下翻转一次"的写法，行话叫 toggle。

（一）三种等价写法，先选最好懂的

写法 特点
if (running == 1) running = 0;
else running = 1;		 本工程采用 最显式：一眼看出"两态互切"，也方便将来在切换时插入动作（如提示音、清屏）。适合初学者把逻辑想清楚
running = !running;最简洁：逻辑非，1 变 0、0 变 1。老手写法
running ^= 1;按位异或翻转最低位。最"硬核"，但对初学者来说可读性差，不推荐一开始就用

三种写法功能完全等价。教学上先用 if/else 把"两个状态互切"的意图写在脸上，等熟练了再享受简写的方便。

（二）为什么 toggle 必须用"放开事件"

📺 复用按键的本质 = 同一个键 + 当前状态 = 不同含义。遥控器的电源键（开 / 关）、手机的音量键、电梯的开门键，全是这个套路。你家里的机顶盒遥控器不会为"开机"和"关机"各做一个键——因为系统记得自己在开还是在关。S5 也是一样：它不关心自己叫"启动键"还是"暂停键"，它只负责让状态翻转一下。

四 main.c 精讲：条件计数与状态显示

概念讲清，看代码。先全文，再逐块精讲——重点在"事件处理段"里新长出来的那两层判断。

（一）main.c 全文

/*
 * 按键按下次数计数控制系统
 * 功能：① S7 计数键（仅"计数中"有效） ② S4 清零键（任何时候有效）
 *       ③ S5 启动/暂停复用键 ④ 第一行标题 ⑤ 第二行"记录次数:"+计数值
 *       ⑥ 第三行工作状态"计数中"/"已暂停"
 */
#include "key.h"
#include "delay.h"
#include "OLED_STC15.h"

unsigned char count = 0;      /* 按下次数计数（0~255，S4 清零） */
unsigned char running = 1;    /* 工作状态：1 = 计数中，0 = 已暂停（开机默认计数） */

void main(void)
{
    Key_Init();                /* 按键初始化：准双向口 + 历史状态清零 */
    OLED_Init();               /* OLED 初始化 */

    OLED_Clear();              /* 清空显存 */
    /* 第一行：标题，6 个汉字宽 96 像素，居中 x=16 */
    OLED_ShowChinese(16, 0, "计数控制系统");
    /* 第二行：标签"记录次数" + 冒号，开机只画一次 */
    OLED_ShowChinese(0, 16, "记录次数");
    OLED_ShowString(64, 16, ":");
    OLED_ShowNum(72, 16, count, 3);   /* 初始次数 000 */
    /* 第三行：初始工作状态"计数中"（与 running 初值 = 1 一致） */
    OLED_ShowChinese(0, 32, "计数中");
    OLED_Update();             /* 把界面先刷上屏 */

    while (1)
    {
        /*
         * 第一阶段：按键事件检测与处理
         * S5 按下放开 → 切换 启动 / 暂停
         * S7 按下放开 → 计数 +1（仅在"计数中"状态下才加）
         * S4 按下放开 → 计数清零
         */
        if (Key_S5_Released() == 1)
        {
            if (running == 1)
            {
                running = 0;           /* 计数中 → 暂停 */
            }
            else
            {
                running = 1;           /* 暂停 → 计数中 */
            }
        }
        if (Key_S7_Released() == 1)
        {
            if (running == 1)          /* 只有"计数中"才加 1，暂停时按 S7 无效 */
            {
                count++;
            }
        }
        if (Key_S4_Released() == 1)
        {
            count = 0;                 /* 清零键不受状态影响 */
        }

        /* 第二阶段：显示当前计数值与工作状态 */
        OLED_ShowNum(72, 16, count, 3);
        if (running == 1)
        {
            OLED_ShowChinese(0, 32, "计数中");
        }
        else
        {
            OLED_ShowChinese(0, 32, "已暂停");
        }
        OLED_Update();

        DelayMs(20);           /* 20ms 扫描周期（隐式消抖） */
    }
}

（二）四个代码块，四件事

代码块 设计要点（讲给学生听）
状态变量区
count + running		 两个全局变量各司其职：count 记"记了多少"，running 记"现在在干嘛"。running 初值 = 1，与第三行开机画面"计数中"对齐
开机界面（三行）
while(1) 之前		 标题、标签、初始状态全部画一次。第三行"计数中"是状态显示的开机快照——它从这一刻起会被主循环接管刷新
S5：翻转状态
if / else 互切		 每按一次把 running 在 0 和 1 之间翻转，用显式的 if/else 把"两态互切"写在脸上；切换后不需要立刻刷屏——同一帧的显示段马上就会按新状态重画
S7：条件计数
两层 if		 外层采事件、内层判状态。暂停时 S7 的放开事件依然被"采"回来，只是被状态挡在门外——计数不受影响，边沿状态也不会乱
显示段
数字 + 状态二选一		 数字每帧刷；状态用 if/else 二选一显示，"计数中"和"已暂停"都是 3 个汉字、各占 48 像素——宽度相等，所以不会留下残影

（三）深挖一层：门控为什么写成"两层 if"

"暂停时 S7 无效"可以用两种写法实现，效果在极端时序下并不相同：

/* ---- 写法 A（本工程采用）：两层 if，事件检测在前、状态放行在后 ---- */
if (Key_S7_Released() == 1)        /* 第一层：无论什么状态，都先把 S7 事件"采"回来 */
{
    if (running == 1)              /* 第二层：状态放行 —— 暂停时事件被挡在门外 */
    {
        count++;
    }
}

/* ---- 写法 B：&& 短路合并（少一层缩进，但埋了一颗雷） ---- */
if (running == 1 && Key_S7_Released() == 1)   /* running==0 时右侧函数根本不执行！ */
{
    count++;
}
对比项 写法 A（两层 if） 写法 B（短路 &&）
暂停时的事件函数照常调用，s7_last 始终跟随真实电平被短路跳过，s7_last 停止更新、与真实电平脱同步
常见时序表现正确表现也正确（所以很容易蒙混过关）
极端时序
（按住 S7 → 用 S5 暂停 → 暂停中松开 S7 → 恢复）		恢复后按 S7 才计一次，干净可能凭"旧账"在恢复瞬间多计一次
职责划分采样归采样、判定归判定，各司其职把"状态判断"和"事件检测"耦合在一行里
🔍 结论：写法 A 更稳，且解释了"为什么"。C 语言的 && 是短路求值——左边为假，右边连算都不算。而 Key_S7_Released() 不只是"看一眼按键"，它内部还有 s7_last 要记账（项目四讲过的事件式检测）。账不记，状态就会脱同步。
写法 A 体现的是"采样与判定分离"的雏形——更成熟的做法是：每帧先把所有按键采样一遍，再统一做状态判定与动作分发。这是后话，但方向已经在这里了。

（二）知识点清单

类别 要点
状态变量用 1 / 0 记录"系统现在处于什么状态"；程序行为 = f(按键, 状态)；初值必须与开机画面一致
状态机思想三要素：状态（哪几格）、事件（什么引发迁移）、动作（每格做什么）；把这三件事分开想清楚，程序自然清晰
复用按键 / toggle一个键两个含义，靠状态区分；每按一次翻转一次；三种等价写法（if/else、!、^=），先用最显式的
触发方式toggle 必须用 Released：用 Down 电平轮询会把"按住 1 秒"当成几十次操作，状态疯狂跳变
条件计数（门控）if (事件) { if (状态) { 动作 } }：外层采事件、内层判状态；避免用短路 && 把两者耦合（会让事件函数"停更"、状态脱同步）
状态显示开机画初始状态快照，主循环按状态二选一刷新；两个状态文字宽度必须相等，否则会留残影
补字模流程查库存 → 生成字模（宋体 16×16、列行式纵向取模）→ 插在结束标记 "" 之前 → 上屏显示验证

（三）易错点排雷

⚠️ 雷 1：用 Down 电平做 toggle
  • 现象：按住 S5 不放，屏幕状态疯狂跳变；手指稍微抖一下也可能翻转两次
  • 根因：电平轮询把"按住"的每一帧都当成一次"按下"
  • 正解：用 Released 放开事件——按下再松开才算一次完整操作
⚠️ 雷 2：状态初值与开机画面不一致
  • 现象：把 running 改成 0（默认暂停），却忘了改开机画面——屏幕上开机显示"计数中"，实际系统却是暂停的，按 S7 没反应，学生一脸问号
  • 教训：状态变量的初值、开机画面、文件头注释，三者必须一起改
⚠️ 雷 3：状态文字不等宽，留下残影
  • 现象：把状态改成"运行 / 已暂停"（2 字 / 3 字）后，暂停时"计数中"的第三个字还留在屏幕上
  • 根因：新字更短，只覆盖了前 32 像素，旧的第三个字没人擦
  • 对策：等宽设计（如"计数中 / 已暂停"），或短的一方补空格，或先 OLED_Clear 再重画

（四）举一反三 · 课后小练习

✏️

练习 1：状态变化时才重画（增量刷新）

加一个 last_running 变量

现在状态文字每帧都重画（虽然多数帧没变）。加一个 last_running，只有"状态变了"那一帧才重画状态文字。体会"增量刷新"——内容不变就不动它。

✏️

练习 2：开机默认"已暂停"

running 初值改 0 + 同步改开机画面

把 running 初值改成 0，同时把开机第三行改成"已暂停"，注释也一起改。做完再想想：如果只改了一处会怎样？——亲身体验"雷 2"。

✏️

练习 3：满 255 自动暂停（状态联动）

count 到 255 时自动进入"已暂停"

在计数处加一句：计数到 255 就把 running 置 0，让系统自己"停下来"，屏幕显示"已暂停"。这是"边界处理"与"状态联动"的结合——下一讲还会用到它。

🚀 下一讲预告：正向 / 反向计数复用按键控制

本讲的系统能"走走停停"了，但它只会做加法——往回数还得靠 S4 一把清零。下一讲给它装上"倒档"：用一个复用键切换正向计数（+1）和反向计数（−1），而且——只在暂停状态下才允许切换方向。

  • 🔄 新变量 dir：0 = 正向、1 = 反向；计数动作变成"看方向办事"：count += (dir == 0) ? 1 : -1;
  • 🚪 准入条件（更严的门控）：S6 切换方向只在 running == 0 时被接受——运行时按键被忽略，系统"不许边跑边换档"
  • ♻️ 复用按键的第二次实战：S6 在暂停时是"换向键"，在运行时"什么都不是"——同一按键的含义再次由状态决定
  • ⚠️ 边界处理登场：反向计数到 0 会回绕到 255；本讲练习 3 的"满 255 自动暂停"思路，正好可以对称地用在下边界上
  • 🖥️ 界面再升级：第四行显示运行方向，"正向 / 反向"的字模需要提前核对补齐
