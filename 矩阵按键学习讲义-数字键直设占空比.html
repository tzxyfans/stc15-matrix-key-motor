1 项目任务与运行效果

在上一讲（*、# 微调 + A/B/C 模式与方向控制）的基础上，启用数字键 0~9：按下的数字在第三行最右侧实时预览，按 D 键确定后才真正写入占空比。

1.1 键位功能总表（本章最终版）

按键功能说明
0 ~ 9数字输入（本讲新增）保留最近两位，第三行最右侧预览，按 D 确定后生效
D参数确定（本讲启用）输入非 0 → 更新占空比；输入为 0 → 不变；确定后预览消隐
* / #占空比 +1 / −1微调，限幅 1~100；不清草稿，预览保留
A模式切换（自动 ↔ 点动）仅停止时有效；不清草稿，预览保留
B / C正转·停止 / 反转·停止自动=边沿复用，点动=电平按住；正反转互锁

1.2 一次完整的操作流程

  1. 上电：占空比 50%，电机停止，自动模式；
  2. 依次按 8、0：第三行最右侧依次显示 08 → 80（预览，电机速度还没变）；
  3. 按 D：预览消隐，"占空比"数字变成 80——参数正式生效；
  4. 按 B：电机以 80% 占空比正转，状态行显示"正转"。
为什么要"预览 + 确定"两步走？ 如果每按一个数字就立刻改速度，输入"80"的过程中电机会先冲到 8% 再跳到 80%，既突兀又危险。先在小角落里预览、按 D 才生效，就像计算器上输完数字再按"="——这是工业面板的标准交互。

对照上一讲，硬件模块（motor / matrix_key）一行没动，所有变化都在 main.c——再次验证"控制框架不动、只加交互"的模块化红利。

3 核心知识①：字符怎么变成数字

按键扫描返回的是字符（ASCII 码），而占空比是数值。中间隔着一座桥：key_evt - '0'。

3.1 字符 ≠ 数字

按键返回的字符ASCII 码（十进制）− '0' 之后
按 0'0'4848 − 48 = 0
按 5'5'5353 − 48 = 5
按 9'9'5757 − 48 = 9

ASCII 表里字符 '0'~'9' 是连续排列的（48~57），所以"字符减 '0'"就得到了它代表的数字。这是 C 语言里最常用的字符→数字转换技巧，不用查表、不用库函数。

3.2 十个 case 合并写

case '0': case '1': case '2': case '3': case '4':
case '5': case '6': case '7': case '8': case '9':
    input_buf = (input_buf % 10) * 10 + (key_evt - '0');
    ShowInputNum(input_buf);       /* 最右侧预览输入数字 */
    need_update = 1;
    break;
语法要点：多个 case 标签叠在一起、中间没有 break，就会"落"到同一段代码——十个数字键共用同一份处理逻辑。这是 switch 里"多个值走同一分支"的标准写法。处理代码里的 key_evt 是实际按下的那个字符，所以 key_evt - '0' 对每个键都能得到正确的数字。

4 核心知识②：两位数的移位拼接

这一行是本讲的"题眼"，读懂它，数字输入就全懂了：

input_buf = (input_buf % 10) * 10 + (key_evt - '0');

4.1 拆开看：取个位 → 升十位 → 加个位

步骤运算作用
① input_buf % 10取旧值的个位把十位"挤掉"，只保留最近按的那个数字
② × 10个位升为十位旧数字左移一位，给新数字腾出个位
③ + (key_evt − '0')填上新的个位本次按下的数字落到个位

4.2 连按三次，看缓冲怎么滚动

为什么用 % 10 而不是判断"已满两位就清零"？ 因为"滚动窗口"的体验更好：输错了不用找退格键，继续按正确的数字，旧的会自己滚出去。按 5、3 发现不对，直接再按 8、0，缓冲就从 53 → 38 → 80 滚到正确值。这就是注释里说的"保留最近两位"。

5 核心知识③：输入缓冲与"确定才生效"

数字进了缓冲区，还没有变成占空比。中间有一道闸门：D 键确定 + input_buf > 0 判断。

5.1 一个变量身兼两职：buf 既是草稿，也是"有没有草稿"

变量类型职责
dutyunsigned char正在生效的占空比（电机听它的）
input_bufunsigned char草稿：存最近两位数字；buf > 0 就表示"有未确认的输入"，无需另设标志位

注意 input_buf 和 duty 是两个变量：按数字键只动草稿，按 D 才把草稿誊到 duty 上——这就是"预览不生效、确定才生效"的实现根基。优化版干脆利落地省掉了 input_active 标志位：草稿的值本身就携带了"是否存在"的信息，0 = 没有草稿，非 0 = 有草稿。

5.2 D 键：确定逻辑逐行讲

case 'D':
    if (input_buf > 0)               /* ① 有草稿且非 0 → 更新占空比 */
    {
        duty = input_buf;
        Motor_SetSpeed(duty);         /* 运行中立即生效，停止时缓存 */
        ShowDutyNum(duty);            /* 左侧正式数字同步更新 */
        input_buf = 0;                /* ② 清零 → 为下一次输入准备 */
    }
    /* input_buf == 0 时占空比不变 */
    ClearInputNum();                  /* ③ 消隐预览（在 if 外，必定执行）*/
    need_update = 1;
    break;
  1. 第①层 if：input_buf > 0 一个条件同时拦住两种不该生效的情况——没按过数字（buf 本来就是 0）和输入了 0（按了 0、0）。占空比合法范围是 1~100，0 会让电机"名义上在转、实际没速度"，程序选择直接拒绝；
  2. ② buf 自清零：写入 duty 后立刻 input_buf = 0。这一行是整个优化版的"闭环"——确认之后草稿作废，下一次输入从 0 开始拼接，不会和这次的旧值混在一起；
  3. ③ ClearInputNum 在 if 外面：无论这次有没有生效，预览区都消隐——哪怕输入 0 被拒，角落里的 "00" 也要擦掉，否则屏幕上挂着一个永远兑现不了的数字。

5.3 优化对比：删掉 input_active，保留"暂时显示"

初版（标志位方案）优化版（本程序，buf 自清零）
判断有没有草稿if (input_active)if (input_buf > 0)——值本身即状态
确认后收尾清标志 + 擦预览（两行成对）buf 清 0 + 擦预览
A / * / # 分支要负责取消草稿（3 处重复代码）完全不管草稿，只管自己的功能
输入中途按别的键草稿被清掉，预览消失草稿与预览保留，回来按 D 仍生效

最后一行就是"保留了数值输入的暂时显示"的含义：输到一半去按 * 微调、或按 B 启动电机，角落里的预览不会消失——它安静地挂在那里，等你回来按 D 才完成使命。这是一个有意为之的取舍：用"草稿多挂一会儿"换"各按键分支互不干扰"的简洁结构。

设计启示：消抖、互锁、标志位……前面学的都是"加东西"；这一处优化演示的是"减东西"——当一个标志的信息能从现有变量的值里推导出来时，标志就是冗余，删掉它，代码反而更不容易出错（少一个需要维护一致性的状态）。

6 输入预览的显示与消隐

预览区只有 16×16 像素，却用到了 OLED 显示的两项基本功：定宽数字与区域擦除。

6.1 两个配套小函数

/* 显示输入预览：第三行最右侧，2 位数字 */
static void ShowInputNum(unsigned char num)
{
    OLED_ShowNum(INPUT_X, 32, num, 2);      /* 定宽2位：05 显示 "05" */
}

/* 消隐预览区：确认或取消后调用 */
static void ClearInputNum(void)
{
    OLED_ClearArea(INPUT_X, 32, 16, 16);     /* 2位数字 = 16px宽 */
}

6.2 为什么显示用 ShowNum 而不是 ShowNumNoZero

占空比数字（X=56）输入预览（X=112）
函数OLED_ShowNumNoZero(x,y,duty,3)OLED_ShowNum(x,y,buf,2)
位数3 位（高位 0 消隐）2 位（高位 0 保留）
效果5 → "　　5"，干净5 → "05"，占位明确
原因正式数值，美观优先输入过程要让人看到"已按了一位"
细节里的人性化：按第一个数字 5 时，预览显示 "05" 而不是 "　5"——高位那个 0 告诉用户"窗口有两位，你刚填了个位"。这正是定宽显示的价值：位数本身也是信息。

6.3 消隐为什么用 ClearArea 而不是写空格

OLED_ClearArea(x, y, 16, 16) 把预览区整块填 0（灭掉所有点），等效于"擦掉"。也可以写两个空格字符，但 ClearArea 更直白、不依赖字库里有空格。区域参数 16×16 与"2 位数字 × 8px 宽、16px 高"精确吻合，不会误擦左边的 % 号（X=80）和正式数字（X=56）。

7 完整按键处理逻辑总览

把 16 个键的处理全部铺开，看主循环的"调度全景"：

结构之美：上一讲搭好的"公共段 + 模式段"骨架原封不动，数字输入只是往公共段的 switch 里加了两个 case。好的框架让新功能像插积木一样接入——这正是模块化设计的回报。

7.1 初学者最易踩的 5 个坑

⚠️ 雷区清单：

  • 忘记字符转数字：直接 buf = key_evt，存进去的是 ASCII 码 53 而不是 5，D 键一确定占空比变成 53%（想要的是 5）——必须 key_evt - '0'；
  • 拼接顺序写反：写成 buf = buf + digit × 10，新数字跑到十位上，越按越离谱；记住"旧的升、新的补"；
  • 确认后忘了 buf 清零：写入 duty 后不执行 input_buf = 0，下次再按 D 会把同一个旧值又写一遍，而且新一轮输入会从旧值上继续拼接（想要 50，先按 5 却变成 85）——自清零是闭环的最后一环；
  • 输入 0 直接生效：不做 buf > 0 判断，按 0、0、D 占空比变 0，电机"在转却不转"；合法范围 1~100 要守住；
  • ClearInputNum 写进 if 里：消隐若只在 buf > 0 分支内执行，输入 0 按 D 时预览 "00" 会永远留在屏幕上——消隐要放在 if 外，无论生效与否都擦。

7.2 举一反三练一练

练习 1：给数字输入加"退格"：长按 * 键时把 buf 除以 10（去掉个位）。提示：buf = buf / 10，想想退到 0 时预览区该显示 "00" 还是直接消隐。

练习 2：输入超过 100（如按 9、9、9 → 99，再按 9 → 99 不会超，但若改成三位窗口呢？）给 D 键加"超过 100 则按 100 处理"的限幅，并在预览区闪烁提示越界。

练习 3：把这套"缓冲 + 预览 + 确认"机制移植到别的参数上：比如用数字键设置一个定时运行的秒数，D 键启动倒计时。
