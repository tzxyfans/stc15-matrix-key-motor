1项目任务与运行效果

本讲任务：把开发板上的 4×4 矩阵键盘用起来——上电后 OLED 显示测试界面，按下任意一个键，第三行就显示它的字符（'0'~'9'、'A'~'D'、'*'、'#'）。这是矩阵按键的"Hello World"：先会读键值，下一讲才能拿它当操作面板去控电机。

⚠️ 动手前先检查跳线（最重要的一步！）

开发板上的跳线 J5 必须短接到【矩阵按键侧】的两个端子。如果 J5 还停在独立按键侧，矩阵键盘的行线/列线根本不通，程序怎么扫都是"无按键"——这是本实验最常见的"按键没反应"原因，不是程序的错，是跳线没拨。

1.1 运行效果：OLED 四行布局

OLED 是 128×64 像素，每行高 16 像素，共 4 行。本讲各字符都是 ASCII（宽 8px），所以布局算账很简单：

行（Y 坐标）内容说明
Y=0Matrix Key Test标题，15 字符×8px=120px，X=(128−120)/2=4 居中
Y=16Key Value:标签，左对齐
Y=32- → 7键值区：初始显示 '-'，按键后显示该键字符
Y=48Press any key...提示语

按一下键盘上的 7，第三行就从 - 变成 7；按 A 就变成 A。按一次只跳一次（松手前不会刷屏），这正是第 5 节要讲的"边沿检测"的功劳。

2为什么用矩阵按键：省一半 IO

前面项目用独立按键，一个按键独占一根 IO——S4~S7 四个键就占了 P3.0~P3.3 四根线。如果产品要 16 个键呢？难道占 16 根 IO？STC15 一共才三十几个可用 IO，太奢侈了。

2.1 矩阵的思想：行 × 列

把 16 个按键排成 4 行 × 4 列的方阵：每个按键接在"某一行线"和"某一列线"的交叉点上，按下时把这一行和这一列连通。这样只需要 4 根行线 + 4 根列线 = 8 根 IO，就能区分全部 16 个交叉点。

方案16 个键需要的 IO找键方式
独立按键16 根（一键一线）哪根线低就是哪个键，直来直去
矩阵按键8 根（4 行 + 4 列）需要"扫描"定位：在第几行拉低时读到了低列

代价也很清楚：独立按键"看一眼就知道"，矩阵按键必须主动扫。怎么扫，就是第 3 节的主角。

2.2 本开发板的接线与键位布局

行线（单片机输出扫描信号）和列线（单片机输入读取状态）由 matrix_key 模块统一定义：

类别引脚方向
行线 ROW1~ROW4P3.0 / P3.1 / P3.2 / P3.3输出（逐行拉低）
列线 COL1~COL4P4.4 / P4.2 / P3.5 / P3.4输入（读谁被拉低）

3逐行扫描原理：一行一行"点名"

矩阵按键的核心算法叫逐行扫描法，思想像老师点名：每次只"喊"一行（把该行拉低），然后看这行的四个学生（列线）谁举手（被拉低）。四轮下来，16 个键全部点到。

3.1 四步流程

  1. 默认：4 条行线全部输出高电平（不扫任何行）；列线写 1 准备做输入。
  2. 扫第 1 行：ROW1=0，其余行保持 1 → 读 4 条列线。若 COL1=0，说明"第1行第1列"的键 7 被按下（因为只有按下键才会把列线接到低电平的行线上）。
  3. 扫第 2 行：ROW2=0，再读列线；然后第 3 行、第 4 行同理。
  4. 都没读到低：说明此刻无键按下，返回 KEY_NONE。

3.2 落到代码：两个内部小函数

扫描的两件小事，matrix_key.c 各用一个 static 内部函数负责（static = 只在模块内部用，不对外）：

/* SetRow：拉低指定行，其余行保持高 */
static void SetRow(unsigned char row)
{
    ROW1 = 1; ROW2 = 1; ROW3 = 1; ROW4 = 1;   /* 先全部拉高 */
    switch (row)
    {
        case 0: ROW1 = 0; break;   /* 只拉低当前行 */
        case 1: ROW2 = 0; break;
        case 2: ROW3 = 0; break;
        case 3: ROW4 = 0; break;
    }
}

/* ReadCol：读 4 条列线，返回被拉低的列号(0~3)，全高返回 4=无键 */
static unsigned char ReadCol(void)
{
    if (COL1 == 0) return 0;
    if (COL2 == 0) return 1;
    if (COL3 == 0) return 2;
    if (COL4 == 0) return 3;
    return 4;
}

3.3 把两个函数串起来：MatrixKey_Read 扫一遍

static unsigned char MatrixKey_Read(void)
{
    unsigned char row, col;
    for (row = 0; row < 4; row++)
    {
        SetRow(row);              /* 当前行拉低，其他行拉高 */
        col = ReadCol();          /* 读列线状态 */
        if (col < 4)             /* 某列被按下 */
        {
            ROW1 = 1; ROW2 = 1; ROW3 = 1; ROW4 = 1;  /* 恢复行线 */
            return key_values[row][col];   /* 查表得键值 */
        }
    }
    ROW1 = 1; ROW2 = 1; ROW3 = 1; ROW4 = 1;      /* 无键，恢复行线 */
    return KEY_NONE;
}

三个细节值得品味：

  • for 循环 = 4 个时间片：一轮循环扫一行，最多 4 轮就把 16 个键查完；
  • 找到就立即 return：不再继续扫后面的行（默认同一时刻只按一个键）；
  • 返回前一定恢复行线为全高：不把某一行留在低电平"占着"，这是好习惯。

4键值映射：code 二维数组

扫描得到的是"第几行第几列"（坐标），怎么变成字符 '5'？答案是查表。

/* key_values[行][列] = 按键字符，布局与实物键盘一致 */
code unsigned char key_values[4][4] = {
    {'7', '8', '9', 'A'},    /* ROW1 */
    {'4', '5', '6', 'B'},    /* ROW2 */
    {'1', '2', '3', 'C'},    /* ROW3 */
    {'*', '0', '#', 'D'}     /* ROW4 */
};

于是 key_values[1][1] 就是 '5'（第 2 行第 2 列）——表的下标和实物键盘的行列一一对应，想改键位定义只动这张表。

💡 code 关键字：把表存进 Flash，不占 RAM

STC15 的 RAM 只有 2KB 左右，金贵；Flash 程序存储器有 60KB，宽裕。这张映射表写好后从不修改，加 code 关键字让编译器把它放进 Flash 而不是 RAM。这是 51 单片机存常量表的标准做法——以后字库、参数表都这么干。

5边沿检测 + 消抖：按一次只认一次

MatrixKey_Read 扫一遍只告诉你"此刻谁按着"。直接拿它去用会有两个麻烦：①按住不放时每次扫描都返回同一个键值，屏幕疯狂重复刷新；②按键触点弹跳（5~10ms）可能把"一次按下"读成"按下-弹开-按下"。对外的 MatrixKey_Scan 就是来解决这两件事的。

5.1 核心：key_now / key_last 边沿检测

unsigned char MatrixKey_Scan(void)
{
    static unsigned char key_last = KEY_NONE;   /* 上次扫描结果，跨调用保持 */
    unsigned char key_now;

    key_now = MatrixKey_Read();              /* 1. 读当前状态 */

    /* 2. 上次无键 + 本次有键 = "刚按下"（下降沿）*/
    if (key_now != KEY_NONE && key_last == KEY_NONE)
    {
        DelayMs(10);                       /* 3. 消抖：等 10ms */
        key_now = MatrixKey_Read();      /* 4. 再读一次确认 */
        if (key_now != KEY_NONE)          /* 5. 还按着 = 有效 */
        {
            key_last = key_now;
            return key_now;               /* 只在"刚按下"返回一次 */
        }
    }
    key_last = key_now;                     /* 6. 记住本次，供下次比较 */
    return KEY_NONE;                        /* 其余时刻一律"无事发生" */
}

5.2 三个设计要点

  • static 局部变量是关键：key_last 声明在函数里却加了 static，函数返回后数值不丢，下次调用还能和"上次"比较——这正是以前独立按键 s4_last 那一套边沿思想，从"单键"推广到了"16 键共用一个变量"；
  • 消抖时机选得巧：不是每帧都延时，只在"刚按下"的下降沿才 DelayMs(10) 再确认一次，平时零开销；
  • 非阻塞：发现按下后不等待松手就直接返回（老式的"等待放开"写法会把主循环卡死几十上百毫秒，电机、显示全停摆）。主循环每轮都会再来问一次，松手后自然又能检测下一次按下。

6main 主程序精讲

有了 matrix_key 模块，主程序非常清爽：初始化 → 画静态界面 → 主循环"扫描 → 有键才更新显示"。

void main(void)
{
    unsigned char key;                 /* 扫描到的键值，无键时为 KEY_NONE(0xFF) */

    MatrixKey_Init();                  /* 矩阵按键端口初始化 */
    OLED_Init();
    OLED_Clear();

    OLED_ShowString(4, 0, "Matrix Key Test");   /* 标题（居中）*/
    OLED_ShowString(0, 16, "Key Value:");       /* 标签 */
    OLED_ShowString(0, 48, "Press any key..."); /* 提示 */
    OLED_ShowString(0, 32, "-");               /* 键值区初始为 '-' */
    OLED_Update();

    while (1)
    {
        key = MatrixKey_Scan();        /* 扫描矩阵按键 */
        if (key != KEY_NONE)           /* 有"刚按下"事件 */
        {
            OLED_ClearArea(0, 32, 16, 16);   /* 先擦旧键值，防残影 */
            OLED_ShowChar(0, 32, key);        /* 写新键值 */
            OLED_Update();                    /* 刷屏 */
        }
    }
}

6.1 值得注意的两点

  • 主循环里没有 DelayMs：以前独立按键项目主循环要带 10~20ms 节拍，这里不需要——MatrixKey_Scan 内部已在"刚按下"时做了 10ms 消抖，平时空转扫描开销极小，键值自然是最新的；
  • 先 OLED_ClearArea 再 OLED_ShowChar：键值区只有一个字符宽，但字符像素形状不同，直接覆盖写会留下上次笔画的残影，先擦一块 16×16 的干净区域再写，这个习惯在 PWM② 已经练过；
  • 键值就是 ASCII 字符：key 直接传给 OLED_ShowChar 显示，不需要任何转换——这正是当初把映射表设计成字符（而不是序号）的回报。

7完整小结与易踩的坑

7.1 一图回顾：从按键到屏幕的链路

环节负责者做什么
硬件4 行线 + 4 列线按键把某行某列连通
定位SetRow + ReadCol逐行拉低，读哪列为低 → 得到（行, 列）
翻译key_values[4][4]（code）坐标 → ASCII 字符
事件化MatrixKey_Scan边沿检测 + 10ms 消抖 → 按一次只报一次
应用main拿到字符，刷新 OLED 第三行

7.2 和独立按键对比着记

对比项独立按键（S4~S7）矩阵按键（本讲）
IO 开销一键一线4+4=8 线认 16 键
检测方式直接读引脚电平必须逐行扫描
按键值固定 S4/S5/S6/S7查表得任意字符
边沿思想s4_last 历史状态key_last（同一招）

7.3 初学者最容易踩的坑

  • ❌ J5 跳线没拨到矩阵侧——扫描永远无键，先查跳线再查程序；
  • ❌ 列线没写 1 就读——准双向口做输入必须先写 1，MatrixKey_Init 里 COL1=1; … 不能省；
  • ❌ 扫完不恢复行线——某行一直拉低，下次扫描全乱；
  • ❌ 不消抖——触点弹跳被当成多次按下；
  • ❌ 用"等待松手"代替边沿检测——主循环被卡死，系统失去响应；
  • ❌ 忘记 static——key_last 每次调用都清零，按住会被当成"每帧都是刚按下"。

7.4 动手练习

① 把第三行的显示从"只显示最新键值"改成"滚动追加"：每按一个键就把字符追加到行尾（满了从头来），提示：维护一个 X 坐标变量。

② 改 key_values 表，让 * 和 # 显示成 E 和 F，体会"键位定义只动一张表"的好处。

③ 思考：如果同时按下两个键，本程序会报哪一个？为什么？（提示：ReadCol 里 if 的顺序 + 找到就 return）
